x86 assembly reference

Registers, Linux syscall conventions, C function arguments, build commands, and flags for i386 and x86-64.

General-purpose registers

i386Full name / conventional role
EAXAccumulator — arithmetic results, function return values, and legacy syscall numbers.
EBXBase register — general-purpose; historically used as a base pointer and for syscall arguments.
ECXCount register — loop counts and shift counts; also a general-purpose register.
EDXData register — paired arithmetic data and I/O; also a general-purpose register.
ESISource index — source pointer for string operations; also general-purpose.
EDIDestination index — destination pointer for string operations; also general-purpose.
EBPBase/frame pointer — often anchors a stack frame; also general-purpose.
ESPStack pointer — points to the current top of the stack.
x86-64Full name / conventional role
RAX64-bit accumulator; low portions are EAX, AX, AH, and AL.
RBX64-bit base register; general-purpose in x86-64.
RCX64-bit count register; used by some instructions and calling conventions.
RDX64-bit data register; used by some instructions and calling conventions.
RSI / RDISource / destination index registers; also used for argument passing on common 64-bit ABIs.
RBP / RSPFrame/base pointer / stack pointer. RSP tracks the current stack top.
R8–R15Additional 64-bit general-purpose registers. Their low 32-, 16-, and 8-bit names end in d, w, and b.

Legacy role names describe common uses, not restrictions: most of these registers can be used as general-purpose registers. The byte and word aliases are the low-order portions of their parent register.

32-bit C function arguments (cdecl)

For the usual 32-bit Linux C ABI, push arguments right-to-left before call. At function entry, the CPU has pushed the return address, so the first argument is at [ESP+4].

OrderCaller actionAt callee entryExample for printf(fmt, msg)
Last argumentpush argN[ESP+4*N]push msg (arg2)
First argumentpush arg1[ESP+4]push fmt (arg1)
Callcall function[ESP] is return addresscall printf
After returnadd esp, 4*NCaller removes arguments (cdecl)add esp, 8

Example sequence: push msg, push fmt, call printf, add esp, 8. Some compiler conventions use callee cleanup; ordinary Linux i386 C uses cdecl. Use db "text", 0 for a C string.

x86-64 C function arguments (System V AMD64)

Integer and pointer arguments are passed in registers first. This is the C function ABI, not the Linux syscall ABI.

ArgumentRegisterExample: printf(fmt, msg)
1RDIformat string
2RSIstring pointer
3RDXthird integer/pointer argument
4RCXfourth integer/pointer argument
5R8fifth integer/pointer argument
6R9sixth integer/pointer argument
7 onwardStackAdditional arguments are passed on the stack
Return valueRAXInteger/pointer result

Before a normal call, align RSP to 16 bytes; at function entry, the pushed return address means RSP % 16 == 8. For variadic calls such as printf, set AL to the number of vector registers used for floating-point arguments (usually zero if none). Example: lea rdi, [rel fmt], lea rsi, [rel msg], xor eax, eax, call printf.

Execution controls

ControlWhat it does
Step InstructionExecutes exactly one machine instruction, then pauses and refreshes the register and instruction views. The Right Arrow key does the same thing. A call instruction enters the called function and steps into it.
Step Over CallEnabled only when the current instruction is a call. Runs the called function and pauses at the instruction after the call returns. Output produced by the call appears in the program output console. It is intentionally unavailable for other instructions.
Run to ExitContinues execution without stopping at each instruction. Pauses if the program hits a debugger stop or signal; otherwise shows its final state and captured output when it exits. A program that does not stop within 120 seconds is stopped and the debugger session is reset.

Build and link commands

Clicking Build & Debug writes your source as program.s in a temporary directory, runs NASM to create program.o, then runs the selected linker to create program. The same commands are printed in the server terminal. The running program's stdout and stderr appear in the output console below the instruction stream. Use Step Over Call to execute a call such as printf without tracing every instruction inside libc, or Run to Exit to continue the program without stepping.

i386 · 32-bit

NASM assembly (both linker choices):

nasm -f elf program.s -o program.o

GNU ld (standalone Linux system-call program with a global _start):

ld -m elf_i386 program.o -o program

GCC (C runtime and libc; source must define a global main):

gcc -m32 -no-pie program.o -o program

x86-64 · 64-bit

NASM assembly (both linker choices):

nasm -f elf64 program.s -o program.o

GNU ld (standalone Linux system-call program with a global _start):

ld -m elf_x86_64 program.o -o program

GCC (C runtime and libc; source must define a global main):

gcc -m64 -no-pie program.o -o program

With ld, the debugger starts at _start; with GCC, it starts at main. GCC links the C runtime and libc automatically; for 32-bit GCC on a 64-bit Ubuntu system, install gcc-multilib and libc6-dev-i386. The 64-bit C calling convention passes arguments in registers; 32-bit cdecl passes arguments on the stack. Use NASM's db directive for null-terminated string data (for example, msg: db "Hello", 0), not dd. Direct ld does not automatically link libc.
